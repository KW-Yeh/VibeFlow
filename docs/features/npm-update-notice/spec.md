# Spec：npm 更新提示與版本顯示

- 狀態：已實作（含從提示開啟更新終端機、設定視窗手動檢查、更新後自動重新啟動 host）
- 需求來源：使用者要求 VibeFlow 執行時每兩小時檢查 npm 新版，並在設定視窗顯示目前版本；2026-10-20 追加「更新完自動重啟 host」，使用者授權直接更新 spec／plan 後實作。

## 目標

讓使用 npm 發佈版的使用者在開著 VibeFlow 時得知新版本已發布，並能在設定中確認目前執行的 host 版本。檢查只提示更新，不自行安裝；安裝由使用者在終端機完成，安裝完成後 host 自行重新啟動以載入新版。

## 行為

- Host 啟動時查一次目前套件的 npm `latest` dist-tag，此後每兩小時查一次；所有 Web UI 共用查詢結果。
- 只有 `latest` 高於執行中的版本時顯示更新提示，並附 `vibeflow update` 與重新啟動說明。
- 更新提示提供「更新 VibeFlow」按鈕。按下後在 host 所在電腦開啟系統終端機；Windows 執行 `vibeflow update`，macOS 與 Linux 執行 `sudo vibeflow update`。終端機顯示 npm 進度和權限提示。
- 無法開啟終端機時在提示內顯示錯誤；按鈕只在 host 已偵測到 npm 新版本時可用，瀏覽器不能指定指令。
- 開啟較晚的 Web UI 也能讀取已查到的更新資訊。使用者可關閉提示；若查到更高版本，提示再次出現。
- 設定視窗顯示執行中的 host 版本，不以 renderer 的建置版本代替。
- 設定視窗在版本旁提供「檢查更新」按鈕：立即重新查詢 npm `latest`，並顯示結果——已是最新版本、目前不是全域 npm 安裝（無法從此更新），或有新版本。有新版本時顯示與提示相同的「更新 VibeFlow」按鈕，開啟同一個更新終端機。
- 手動檢查與定期檢查共用 host 端的結果：手動查到新版本時，看板上的更新提示也會出現；手動查詢失敗時顯示錯誤原因，但保留上次成功的結果。
- 原始碼執行不查 npm：原始碼套件名稱不是發佈名稱，且 `vibeflow update` 不適用。
- 定期檢查時 npm 無法連線不顯示錯誤提示；已成功取得的版本資訊保留到下次成功查詢。

## 更新後自動重新啟動

- 全域 npm 安裝的 host 會注意磁碟上已安裝的版本。偵測到比執行中版本更高、且已完整可執行的新版時，host 自動重新啟動成新版，不論更新是從提示按鈕或使用者自行執行 `vibeflow update` 觸發。
- 重新啟動沿用同一個 port、store 與 session 後端，也沿用同一個 token：已開著的 Web UI 分頁不需重開網址，重新連線後若 host 版本改變會自動重新整理頁面，載入新版介面。
- 原本啟動 host 的終端機繼續顯示新 host 的輸出，Ctrl+C 仍可停止 host。
- 重新啟動不以 root 身分執行：重新啟動由 host 自己（使用者身分）完成，`sudo vibeflow update` 只負責安裝。
- 不自動重新啟動、改為在更新提示中說明「新版已安裝，請手動重新啟動 host」的情況：
  - host 使用 pty 後端且有執行中的 session（重啟會中斷 agent）；session 全部結束後會自動重新啟動。
  - host 是 TUI（`vibeflow tui` 自己成為 host 時）。
- tmux 後端的 session 在重新啟動時繼續執行，新 host 接回。
- 原始碼執行不適用。

## 驗收

- 版本比較只將較高的 npm 版本判定為更新。
- 檢查間隔為兩小時，失敗不影響 host 啟動或運作。
- Web UI 能顯示、關閉更新提示，並在收到更高版本事件後再次顯示。
- 按鈕呼叫 host 開啟更新終端機；開啟失敗時顯示原因。
- 設定視窗顯示 `app:getVersion` 回傳的版本。
- 設定視窗的「檢查更新」呼叫 `host:checkUpdate`，正確顯示失敗、已是最新、有新版本三種結果；有新版本時的按鈕呼叫 host 開啟更新終端機。
- 磁碟上的已安裝版本只有在高於執行中版本、連續兩次讀到相同版本，且新版 CLI 能執行並回報該版本時才判定為「已安裝完成」。
- 判定完成後，Web UI host 以相同 port、store、後端與 token 重新啟動；原終端機持續接收新 host 輸出，結束碼為新 host 的結束碼。
- Web UI 重新連線後發現 host 版本不同時重新整理頁面。
- pty 後端有執行中 session 或 host 為 TUI 時不重新啟動，更新提示改為「已安裝 vX，請手動重新啟動」並說明原因；pty session 全部結束後自動重新啟動。
- 傳給新 host 的 token 不會留在新 host 的環境變數中（agent session 讀不到）。
