## 問題與目標

Issues & PRs 檢視（`docs/features/github-issues-prs/`）目前只能用單選的「專案」篩選，
排序依建立時間新到舊。項目一多就難以找到要處理的那張。

目標：在 Issues & PRs 檢視加入「專案」「Assignee」「發起人」三個非必填、可任意組合的篩選，
並讓結果依專案分組、組內依 `#編號` 由大到小排列，方便快速找到目標項目。

另外，PR 被我 approve 後 GitHub 會撤掉 review request，這類仍 open 的 PR 目前就從清單消失；
要讓「我 review 過、尚未關閉」的 PR 也留在清單中。

## 範圍

### 本次包含

- Issues & PRs 檢視頂列的篩選改為三個複選下拉：專案、Assignee、發起人（取代現有單選的專案篩選）。
- 篩選的選項由目前抓到的 Issue／PR 動態彙整。
- 一鍵清除所有篩選。
- Issues、Pull Requests 兩欄的排序改為：先依專案名稱，組內依編號由大到小。
- 側邊欄「專案」列的點擊改為操作新的專案複選篩選。
- PR 的抓取範圍加入「我 review 過的 open PR」（`reviewed-by:@me`）；頂列說明文字與 PR 欄空狀態文案同步改寫。

### 本次不包含

- 看板（Board）檢視的專案篩選——維持現有單選，不改。
- 文字搜尋、label／Issue Type／狀態等其他篩選。
- 篩選條件留存（localStorage、URL、store 都不寫）。
- 其他抓取範圍變動：Issue 仍是「指派給我、我建立」；PR 只多「我 review 過」一類。篩選只在已抓到的資料上過濾。
- 「與我的關係」篩選（例如只看我 review 過的）。
- 改變側邊欄專案列 Issue · PR 數量的意義（仍是未篩選的總數；因 PR 範圍變大，數字可能增加）。
- TUI。

## 行為

| 情境或觸發條件 | 預期行為 |
| --- | --- |
| 未設定任何篩選 | 顯示全部項目（與現在相同），三個按鈕分別顯示「所有專案」「所有 Assignee」「所有發起人」 |
| 開啟任一篩選下拉 | 列出可勾選的選項，已勾選的帶勾號；勾選／取消後下拉保持開啟、清單立即更新；點外部或 Esc 收起 |
| 專案選項 | 有 GitHub repo 的看板專案名稱，依名稱排序 |
| Assignee 選項 | 最上方「未指派」，其後是目前所有 Issue／PR 的 assignee login，依名稱排序、去重 |
| 發起人選項 | 目前所有 Issue／PR 的 author login，依名稱排序、去重 |
| 同一篩選勾選多個值 | 符合其中任一個即顯示（OR）；選「未指派」= 沒有任何 assignee 的項目 |
| 多個篩選同時設定 | 必須同時符合每一個有設定的篩選（AND）；沒設定的篩選不限制 |
| 篩選按鈕文字 | 沒勾 = 「所有…」；勾一個 = 該值；勾多個 = 「<篩選名> · N」 |
| 已勾選的值在重新整理後不再出現於資料中 | 仍保留在選項中並維持勾選，使用者可自行取消；該值不符合任何項目 |
| 有任一篩選生效 | 頂列出現「清除篩選」，按下後三個篩選同時清空 |
| 篩選後某欄沒有項目 | 該欄顯示「沒有符合篩選條件的 Issue」／「…的 PR」；沒有篩選時沿用現有空狀態文案 |
| 欄位標頭數量 | 顯示篩選後的數量 |
| 已開啟詳情抽屜的項目被篩掉 | 抽屜關閉 |
| 單一 repo 抓取失敗的錯誤列 | 只列出符合專案篩選的 repo（沒選專案時全部列出），與現在相同 |
| 排序 | 每欄先依專案名稱（與專案選項同序），同專案內依 `#編號` 由大到小 |
| 點側邊欄某專案 | 切到 Issues & PRs，專案篩選改為只勾該專案；若專案篩選已經是只勾該專案，則清空專案篩選。Assignee／發起人篩選不受影響 |
| 側邊欄專案列的選取樣式 | 在 Issues & PRs 檢視中，被勾選的專案都呈選取樣式 |
| 重新整理頁面或重開 app | 篩選回到全部 |
| 我 review 過（approve、要求修改或留 review comment）、仍 open 的 PR | 出現在 Pull Requests 欄，與其他 PR 一樣可被三個篩選過濾；同一 PR 符合多種條件時只出現一次 |
| 頂列說明文字 | 「<login> · 指派給我、我建立、我 review 的」 |
| PR 欄沒有任何項目（未篩選） | 「沒有指派給你、你建立、請你 review 或你 review 過的 open PR」 |

## 驗收條件

- [ ] AC-1：頂列有「專案」「Assignee」「發起人」三個下拉，選項依「行為」表彙整；可複選且下拉在勾選後保持開啟。
- [ ] AC-2：同一篩選多選為 OR、跨篩選為 AND；不設定的篩選不限制；「未指派」只留下沒有 assignee 的項目。
- [ ] AC-3：兩欄都依專案名稱分組、組內編號由大到小排列，篩選前後皆然。
- [ ] AC-4：欄位數量、空狀態文案、錯誤列、詳情抽屜依「行為」表反映篩選結果；「清除篩選」一次清空全部。
- [ ] AC-5：側邊欄點專案依「行為」表操作專案篩選並顯示選取樣式；看板檢視的專案篩選行為不變。
- [ ] AC-6：重新整理頁面後篩選回到全部，store 與瀏覽器儲存中沒有新增篩選資料。
- [ ] AC-7：我已 approve（review request 已撤除）但仍 open 的 PR 出現在 Pull Requests 欄且只出現一次，可被三個篩選找到。

## 限制與依賴

- 篩選與排序是純 renderer 改動；core 只在 `fetchRepoItems` 多一個 `gh pr list --search reviewed-by:@me` 查詢
  （每個 repo 每次抓取多 1 次 `gh` 呼叫），資料形狀與 handler table 都不變。
- 視覺沿用 `docs/DESIGN.md`／`globals.css` token 與 `test/ui-consistency.test.mjs` 規則；下拉樣式延續現有 `ProjectFilter`。
- 頂列寬度有限：三個篩選加上右側「<login> · 指派給我、我建立的 · N 分鐘前更新」，右側文字沿用現有截斷行為。
- 不新增留存資料，不需 migration。
