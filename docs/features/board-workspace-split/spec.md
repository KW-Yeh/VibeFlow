## 問題與目標

看板頁目前上下分割：上半是看板欄位，下半是任務工作區（分頁列＋終端機＋右側資訊欄），兩者以可拖曳的分隔線（`vibeflow:board-split-px`）分配高度。終端機與看板搶同一條垂直空間：看板拉高，終端機只剩幾十行；終端機拉高，看板只看得到每欄最前面幾張卡。

目標：看板與工作區各自成為獨立頁面、各自佔滿全高。工作區內部的版面（工具列、終端機、右側資訊欄 rail）**原樣保留**，只改它與看板的位置；工作區左側加一條可收合的精簡任務清單，讓使用者不必回看板就能切換任務並看到其他卡的狀態。

## 範圍

### 本次包含

- 側欄（`SideMenu`）新增「工作區」入口，與「看板」「工作項目」「終端機」並列。
- 看板頁只顯示看板欄位（`BoardColumns`），佔滿全高；移除上下分隔線。
- 新增工作區頁：左側任務清單＋右側原有 `TaskWorkspacePanel`。
- 左側任務清單：只列 In Progress 的卡，每列顯示狀態點、標題、專案、待辦進度、待確認標記、Master／子卡關係；可收合成窄條。
- 左側任務清單取代目前的工作區分頁列（`TerminalTabBar`）。
- URL 與本機偏好：新增 `?view=workspace`，舊網址與舊 localStorage 鍵的處理（見「行為」）。

### 本次不包含

- 工作區內部版面（工具列、終端機、右側資訊欄 rail 的停駐／收合行為，見 `docs/features/workspace-layout/`）不變。
- 「終端機」格狀頁（`TerminalGrid`）與「工作項目」頁不變；兩者與工作區是否合併另議。
- TUI 不變。
- 彈出獨立瀏覽器視窗（原方案 D）不做。
- core、handler table、store 形狀不變——這是純 renderer 改動。

## 行為

| 情境或觸發條件 | 預期行為 |
| --- | --- |
| 在看板點一張卡（任何欄位） | 切到工作區頁並選中該卡 |
| 開始一張 Backlog 卡（工作區裡的「開始」） | 留在工作區，該卡移到左側清單頂端；回看板時卡片在 In Progress 欄。看板沒有拖曳（實作調查時確認），Q2 的「拖進 In Progress」對應的就是這個「開始」 |
| 在工作區點左側清單的一列 | 右側換成該卡的工作區，不離開工作區頁 |
| 左側清單的內容 | 只列 In Progress 的卡，順序與看板 In Progress 欄相同；沒有進行中的卡時顯示「目前沒有進行中的任務」 |
| 從看板點開 Backlog 或 Done 的卡 | 工作區顯示該卡（沿用現有 Backlog／Done 版面）；左側清單只列 In Progress 卡，不列這張卡（2026-11-10 移除「目前檢視」列：容易被誤認為進行中的卡，卡片內容在看板的任務詳情就看得到） |
| 卡片離開 In Progress（完成、退回 Backlog） | 從左側清單移除；若它正被選中，畫面不跳走 |
| 左側清單收合 | 收成窄條，只剩每張進行中卡的狀態點；展開／收合狀態記在本機，重整後保留 |
| 視窗寬度低於 1280px，且使用者從未切換過收合狀態 | 左側清單預設收合：展開的清單加上固定的右側資訊欄，會讓終端機窄到工具列重疊（實測 1024px 時只剩約 320px）。使用者自己展開後就照他的選擇 |
| 卡片需要權限確認、或 agent 完成 | 清單該列顯示「待確認」或對應狀態，與看板卡片使用同一套狀態來源（`progress`） |
| 工作區頁沒有選中任何卡 | 顯示空狀態：「從左側選一張卡片，或建立新的任務」＋「新增任務」按鈕 |
| 選中的卡被刪除（本機或 CLI） | 選取清空並顯示空狀態，與現行行為一致 |
| 在看板與工作區之間來回切換 | 終端機不重新啟動、不遺失畫面：In Progress 卡的工作區一律保持掛載，切頁只是隱藏 |
| 開啟 `?view=workspace&task=<id>` | 直接進入工作區並選中該卡；id 不存在時顯示空狀態 |
| 點側欄「工作區」但目前沒有選中卡 | 選中左側清單第一張卡；清單為空則顯示空狀態 |
| 開啟舊網址 `?task=<id>`（沒有 view） | 進入工作區並選中該卡（舊網址的意思是「看這張卡的工作區」）。看板頁有選取時網址改寫成 `?view=board&task=<id>`，重整後仍停在看板 |
| 舊的 localStorage 鍵 `vibeflow:board-split-px`、`vibeflow:terminal-tabs` | 不再讀取，啟動時移除 |
| 側欄「新增任務」 | 行為不變（開新增任務對話框），不切換頁面 |

## 限制與依賴

- 終端機生命週期與元件掛載綁定（`task-terminal.tsx`）：切頁必須用隱藏而非卸載，沿用 `home.tsx` 目前讓 `TerminalGrid` 以 `hidden` 保持掛載的做法。
- `BoardView`（`renderer/components/ui/view-tabs.tsx`）是 `SideMenu`、`InboxView`、`TerminalGrid`、`view-persistence.ts` 共用的型別；新增值要檢查所有使用端。
- 左側清單的狀態標示需與看板卡片（`board-columns.tsx`）共用同一份資料（`progress`、`taskLinks`），避免兩處顯示不一致。
- `docs/DESIGN.md` 的 token 與 `test/ui-consistency.test.mjs` 的規則（radius 階梯、`focus-visible:ring-[3px]`）適用於新元件。
