## 問題與目標

卡片之間的訊息（目前只有 master 與它自己的卡片互傳，`vibeflow:sendMessage`）送出後，如果收件卡的 agent 正在工作，訊息會先在收件卡的 inbox 或 host 記憶體裡等。現在看不到哪些訊息還在等、等了多久，也看不到誰在什麼時候說過什麼。訊息檔一被 agent 的 hook 讀走就刪掉，沒有留下紀錄。

目標是在 Web UI 加一套訊息介面：

- 有還沒被讀到的訊息時，畫面角落浮出對話泡泡，每組「來源卡 → 收件卡」一顆。
- 點開泡泡是對話框，可以看這組卡片的完整訊息紀錄（誰、什麼時間、說了什麼、已讀或未讀）。
- 使用者看到未讀訊息時，可以手動讓它立刻送進收件卡的 session，不必等原本的送達時機。
- 使用者可以在對話框裡自己打字傳給收件卡。

訊息仍然照現在的規則自動送達。這個功能不攔訊息、不要求人確認，只多了紀錄、顯示和「立刻送」。

## 範圍

### 本次包含

- core 留存每則卡片訊息的紀錄，包括寄件者、收件卡、內容、送出時間、狀態，以及已讀的時間與方式。
- 判斷每則訊息是未讀還是已讀，狀態改變時推事件給所有 frontend。
- 新增 handler，讓 frontend 讀取對話紀錄、讓未讀訊息立刻送進 session、以使用者身分傳訊息給一張卡。
- Web UI 的對話泡泡、對話框和頂列的「訊息」按鈕，依設計稿實作。泡泡在看板頁和任務詳情頁（工作區）都會出現。
- 刪除卡片時刪掉以這張卡為來源或收件者的紀錄。

### 本次不包含

- TUI 的訊息介面。
- VibeFlow host 自己送出的通知（`notifier.ts` 給 master 的 launchError、全部完成，以及額度用完後的 continue）。這些訊息不記錄、不顯示泡泡。
- 放寬 `NOT_RELATED` 規則。卡片之間能不能互傳維持現狀，只有「你」可以傳給任何正在執行的卡片。
- 中斷正在工作的 agent。「立刻送」不會按 Esc 或 Ctrl+C。
- 改變 Codex 的送達方式，或替 Codex 偵測權限對話框。

## 行為

### 名詞

- 對話：一組「來源 → 收件卡」。來源是一張卡或「你」。B 回覆 A 是另一組對話（B → A）。
- 你傳的訊息：在「A → B」的對話框裡打字，訊息以「你」的身分送給 B，顯示在這組對話的右側。系統另外記成「你 → B」，但畫面上歸在你當時打開的那組對話裡。
- 未讀：VibeFlow 已經收下訊息，但收件卡的 agent 還沒讀到。可能是在 inbox 等 hook 讀走，也可能是在 host 記憶體等輸入框清空。
- 已讀：agent 已經讀到，方式是 hook 帶入（`via: 'hook'`）或打進 terminal（`via: 'typed'`）。

| 情境或觸發條件 | 預期行為 |
| --- | --- |
| master 傳訊息給它的卡片，收件卡 agent 正在工作 | 訊息照現在的規則進 inbox 或排隊，紀錄記成未讀。畫面右下角浮出「master → 卡片」泡泡，顯示最新一則的摘要和未讀數。 |
| 同一組來源和收件卡又傳一則 | 不新增泡泡，同一顆泡泡的未讀數加一，摘要換成最新一則。 |
| agent 的 hook 讀走訊息，或 host 把它打進 terminal | 紀錄改成已讀，記下時間和方式，未讀數減一。 |
| 一組對話全部已讀 | 泡泡留著，改成灰點、沒有數字，可以按 × 收起。收起後這組有新訊息時再浮出。 |
| 超過 4 組對話有泡泡 | 最上面顯示「+N 則對話」，點了展開全部。 |
| 在任務詳情頁（工作區）打開一張卡 | 泡泡浮在右側面板的右下角，不蓋住 terminal。和這張卡有關的對話（它是來源或收件卡）排在最下面，標「這張卡」，其他對話照常排在上面，中間用分隔線隔開。左側卡片列表上，有未讀訊息要給它的卡片顯示未讀數。 |
| 點泡泡 | 打開對話框，依時間列出這組對話的所有訊息，以及你在這個對話框裡傳給收件卡的訊息。每則顯示寄件者、時間、內容和狀態。標題列顯示收件卡 agent 的狀態（工作中、閒置、等待權限、沒在執行）。 |
| 在未讀訊息上按「立即送進 session」 | 不再等 agent 閒下來或等你停手 3 秒，直接把這則（含 inbox 裡排在它前面、同一張收件卡的未讀訊息）打進收件卡的 terminal。成功後狀態改成已讀、打進 terminal。agent 正在工作時，訊息會進 agent CLI 自己的輸入佇列，由它決定何時處理。 |
| 按「全部立即送出」 | 收件卡所有未讀訊息合成一次輸入送出，規則同上。 |
| 收件卡停在權限對話框時按立即送 | 拒絕（`TARGET_BLOCKED`），訊息維持未讀，提示先到 terminal 處理。 |
| 收件卡輸入框有你還沒送出的文字時按立即送 | 拒絕，訊息維持未讀，提示先送出或清掉那段文字。 |
| 收件卡 agent 沒在執行 | 輸入框和「立即送進 session」停用並說明原因。訊息留在 inbox，下次啟動時由新 session 讀到。 |
| 在對話框輸入文字按 Enter 或送出 | 輸入框和送出按鈕同高、並排對齊。輸入多行時輸入框往上長高（最多 6 行），送出按鈕對齊輸入框底部。訊息以「你」的身分傳給收件卡，走跟卡片訊息一樣的送達流程。訊息顯示在右側，狀態照實際送達結果更新。Shift+Enter 換行。空白訊息不送，超過 20,000 字拒絕。 |
| 頂列「訊息」按鈕 | 徽章顯示所有對話的未讀總數。點了列出所有有紀錄的對話（包括已收起的），點一組打開它的對話框。 |
| 重新整理頁面或重啟 host | 紀錄還在，未讀或已讀照實際狀態顯示。泡泡收起與否是每個瀏覽器自己的偏好。 |
| 刪除一張卡 | 以它為來源或收件者的紀錄一起刪掉，對應的泡泡消失。 |
| 卡片進入已完成 | 紀錄保留，對話框可以讀，但輸入框和立即送停用。 |

所有顯示給人看的文字用繁體中文，欄位名稱照 `column-labels.ts`。

## 限制與依賴

- 送達仍然全部經過 `mailbox.ts`。「立刻送」不能違反它的既有規則：不打進權限對話框（Claude 卡片）、不疊在使用者未送出的文字上、不被其他寫入切開。
- Claude 卡片的已讀要靠 inbox hook 讀走檔案這件事判斷。hook 目前讀完就刪檔，所以 core 必須能把「檔案消失」對應回紀錄裡的那則訊息。
- Codex 卡片沒有權限對話框偵測（AGENTS.md 已記載），立即送時無法擋下打進權限對話框的情況。
- 紀錄是新的留存資料，放在 store 目錄下，不寫進 `vibeflow-state.json`。沒有舊資料要遷移，但格式要能往後擴充。
- 新的 handler 必須照 handler table 的慣例驗證參數、只收 task id，並同步更新 `packages/core/IPC_API_MAP.md`。
- UI 依設計稿與 `docs/DESIGN.md` 的 token，用 shadcn token class，不用寫死的顏色。

## 已定案的決定

- 「你」傳的訊息歸在你當時打開的那組對話（例如 master → B 的對話框），不另開「你 → B」的泡泡。
- 紀錄保留到卡片刪除為止，不設上限。
